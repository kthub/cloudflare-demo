Cloudflare Workers · Static Site

静的サイトの
公開ガイド

Cloudflare で静的HTMLを無料で公開する手順です。

用意するもの

  • Cloudflareアカウント（無料）
  • 公開するHTMLフォルダ
STEP 1 — 公開URLの調整 初回だけ

Cloudflare で公開したサイトは、初期状態では workers.dev ドメインで配信されます。このときのURLは次の3つの部分でできており、真ん中のサブドメインはアカウント共通の値として、好きな名前に設定できます。公開を始める前に一度だけ決めておきます（以降は変更不要）。

my-siteWorker名 . sub-domainサブドメイン . workers.dev固定

サブドメインを好みの名前に変更する手順:

  1. Workers & Pages を開く
    ダッシュボードの Workers & Pages ページへ。
  2. 「Your subdomain」の Change を押す
    ページ内の Your subdomain の横にある Change を選択。
  3. 新しい名前を入力して保存
    使いたいサブドメイン名を入力して確定。以降このアカウントのWorkerはすべて <Worker名>.<新サブドメイン>.workers.dev になる。
!
サブドメインはアカウント単位の設定です。変更すると同じアカウントの全WorkerのURLに反映されます。Change が見当たらない・変更できない場合は、Cloudflareサポートへの問い合わせが必要です。
STEP 2 — サイトを公開する

3つの方法があります。お試しなら①、設定ファイルで管理するなら②、Gitと連携して自動更新するなら③。

ドラッグ&ドロップ

ダッシュボードにファイルをアップロードするだけの、最も手軽な方法。

  1. Workers & Pages を開く
    ダッシュボードの Workers & Pages へ。
  2. アップロード方式を選ぶ
    Create application → Upload and deploy を選ぶ。
  3. ファイルを入れて Worker 名を決める
    フォルダか zip をドラッグ&ドロップし、Worker name を入力。この名前がURLの先頭になる。
  4. デプロイ
    Deploy を押して完了。
公開URL
https://<Worker名>.<サブドメイン>.workers.dev
!
ファイル名が index.html でない場合、ルート（.../）では開けず .../<ファイル名> でのアクセスになります。ルートで開きたければ index.html にリネームを。

Wrangler（CLI）

設定ファイルで管理する方法。CI組み込みやチーム運用に向く。

  1. インストールしてログイン
    # Node.js / npm が前提
npm install -g wrangler
wrangler login
  2. 設定ファイルを作る
    プロジェクトルートに wrangler.jsonc を作成。静的アセットのみなら最小構成はこれだけ。
    {
  "name": "my-site",           // ← URL先頭になる
  "compatibility_date": "2026-06-01",
  "assets": {
    "directory": "./public/"   // 公開フォルダ
  }
}
  3. デプロイ
    wrangler deploy
公開URL
https://my-site.<サブドメイン>.workers.dev

Git連携（Workers Builds）

リポジトリと連携し、git push で自動ビルド&デプロイする方法。

  1. リポジトリを接続
    Workers & Pages → Create application から GitHub / GitLab のリポジトリをインポート。
  2. ビルド設定
    静的HTMLなら Build command は空欄。公開フォルダ（assets.directory 相当）を指定。
  3. デプロイ
    以降は push で自動更新。プレビューURLも付く。
公開URL
https://<Worker名>.<サブドメイン>.workers.dev
